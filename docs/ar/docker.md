# تشغيل Docker والنشر والاختبارات

يستخدم المشروع ملف Dockerfile واحدًا وينتج صورتين مختلفتين:

- `runtime`: صورة الإنتاج لتشغيل CLI وMCP، وهي الهدف الافتراضي.
- `ci`: صورة اختبار واحدة بمعمارية AMD64، تجمع متطلبات المتصفح ووسائل النقل الأصلية.

صورة CI ليست مخصصة للنشر. فهي تحتوي على المترجمات وترويسات التطوير واعتماديات Composer الخاصة بالتطوير وNode.js وChromium وphp-rnet وcurl-impersonate.

## المتطلبات

- Docker Engine أو Docker Desktop مع تفعيل Buildx.
- دعم BuildKit؛ يستخدم Dockerfile آليات التخزين المؤقت الخاصة به.
- لتشغيل مجموعة CI الكاملة: إمكانية بناء وتشغيل `linux/amd64`.
- على أجهزة Apple Silicon، يجب إعداد محاكاة AMD64 في Docker أو Colima قبل تشغيل المجموعة الكاملة. اختبارات وسائل النقل الأصلية مقيدة عمدًا بـ Linux AMD64.

تحقق من التثبيت:

```bash
docker version
docker buildx version
docker buildx ls
```

## صورة الإنتاج

ابنِ الهدف الافتراضي:

```bash
docker buildx build \
  --file docker/Dockerfile \
  --target runtime \
  --load \
  --tag webtrawler:local \
  .
```

تشغيل أمر:

```bash
docker run --rm webtrawler:local version

docker run --rm webtrawler:local \
  fetch https://example.com/ --block-private --markdown
```

تستخدم الصورة PHP CLI على Alpine، وتحتوي على اعتماديات Composer اللازمة للإنتاج فقط. تنسخ المجلدات `bin/` و`src/` و`config/`، ولا تنسخ مجموعة الاختبارات أو اعتماديات التطوير أو مجلد `vendor/` الموجود على جهاز المضيف.

### حفظ مخرجات الزحف

تعمل الصورة بالمستخدم غير المميز UID `10001` (`scraper`)، ويكون `/out` مجلد العمل. اربط مجلدًا من المضيف به عند الحاجة إلى الاحتفاظ بالمخرجات أو حالة الاستئناف بعد حذف الحاوية:

```bash
mkdir -p out
docker run --rm \
  --mount "type=bind,source=$PWD/out,target=/out" \
  webtrawler:local \
  crawl /spiders/books.php \
  --format jsonl \
  --output /out/books.jsonl \
  --state /out/books.state.json \
  --robots
```

إذا كان ملف Spider على المضيف، اربطه للقراءة فقط:

```bash
docker run --rm \
  --mount "type=bind,source=$PWD/spiders,target=/spiders,readonly" \
  --mount "type=bind,source=$PWD/out,target=/out" \
  webtrawler:local \
  crawl /spiders/books.php --format jsonl --output /out/books.jsonl
```

تأكد من أن مجلد المخرجات على المضيف قابل للكتابة بواسطة UID `10001` داخل الحاوية، أو اضبط الملكية والصلاحيات قبل التشغيل.

### خصائص التشغيل

صورة الإنتاج:

- تعمل بالمستخدم غير المميز `scraper`.
- تكتب مخرجات الزحف تحت `/out`.
- تعطل PHP assertions.
- تضبط حد ذاكرة PHP على `512M`.
- تحتوي على اعتماديات الإنتاج فقط.

حد الذاكرة مضبوط في `ENTRYPOINT` الخاص بالصورة. إذا احتاج التطبيق إلى حد مختلف، أنشئ صورة مشتقة أو غيّر `ENTRYPOINT` صراحة؛ لا تفترض أن متغير بيئة وقت التشغيل سيغير إعداد PHP هذا.

### أمان الشبكة

لا تنشئ الصورة حدًا أمنيًا للشبكة. عند التعامل مع عناوين URL غير موثوقة:

- فعّل حماية الشبكات الخاصة في أداة الزحف واضبط قائمة المضيفين المسموح بها.
- اترك التحقق من TLS مفعّلًا.
- قيّد الاتصالات الصادرة من الحاوية على مستوى مضيف Docker أو الجدار الناري أو Egress Proxy عندما يتطلب نموذج التهديد ذلك.
- لا تعتبر فحوص URL على مستوى التطبيق حماية كاملة من DNS rebinding.

راجع [خيارات HTTP والأمان](http-and-security.md) و[تشغيل المتصفح](browser.md).

## مجموعة اختبارات Docker كاملة

شغّل جميع فحوص Docker من خلال أمر Composer واحد:

```bash
composer test-docker
```

ينفذ الأمر `docker/test.sh` الخطوات التالية:

1. يبني هدف `ci` الواحد بمعمارية `linux/amd64`.
2. يبني صورة الإنتاج وينفذ اختبارات Smoke الخاصة بها باعتبارها اعتمادًا لازمًا لبناء صورة CI.
3. يحمّل صورة CI واحدة إلى محرك Docker المحلي.
4. يشغّل الحاوية مرة واحدة مع تعطيل الاتصال بالشبكات الخارجية.
5. ينفذ اختبارات Playwright/Chromium وImpity/curl-impersonate وphp-rnet بالتتابع.
6. يعتبر تخطي أي اختبار تكامل مطلوب سببًا للفشل.

الاسم الافتراضي لصورة الاختبار هو `webtrawler:ci`. يمكنك تغييره دون تعديل السكربت:

```bash
WEBTRAWLER_CI_IMAGE=webtrawler:ci-local composer test-docker
```

يستخدم السكربت عرض البناء `plain` افتراضيًا. لتغيير طريقة العرض:

```bash
DOCKER_BUILD_PROGRESS=auto composer test-docker
```

تنفذ الاختبارات بالتتابع عمدًا. كما تستخدم عملية بناء php-rnet وامتدادات PHP عامل بناء واحدًا افتراضيًا لتقليل استهلاك الذاكرة عند محاكاة AMD64.

### ما الذي تغطيه الاختبارات؟

| الفحص | وقت التنفيذ | ما الذي يتحقق منه؟ |
|---|---|---|
| Runtime smoke | أثناء بناء صورة CI | امتدادات الإنتاج، UID غير المميز، محتويات الإنتاج فقط، تشغيل CLI، جلب HTTP محلي، ومنع العناوين الخاصة |
| Browser integration | عند تشغيل حاوية CI | تشغيل Chromium، والتقاط الاستجابات، واستمرار الجلسات، والتحليل التكيفي، ومنع الاتصال الخارجي |
| Impity integration | عند تشغيل حاوية CI | ملف curl-impersonate الحقيقي وسلوك التحويلات المحلية وسياسة المضيف وحد حجم الاستجابة |
| php-rnet integration | عند تشغيل حاوية CI | الامتداد الأصلي المبني وموائم RNet الحقيقي مع خادم الاختبار المحلي |

تعمل اختبارات المتصفح ووسائل النقل داخل الحاوية نفسها، لكنها تنفذ كمجموعات منفصلة ومتتابعة. تبدأ الحاوية باستخدام `--network none`، ولا يتم تفعيل اختبار عزل المتصفح إلا لهذا التشغيل المعزول.

## أهداف البناء والتخصيص

| الهدف | الغرض | الاستخدام |
|---|---|---|
| `runtime` | صورة الإنتاج لـ CLI وMCP | النشر |
| `smoke` | صورة الإنتاج مع فحوص Smoke وقت البناء | اعتماد لصورة `ci`، ويمكن بناؤه منفردًا للتشخيص |
| `transport-ci` | مرحلة بناء وسائل النقل الأصلية | مرحلة داخلية تستخدمها `ci` |
| `ci` | صورة اختبار موحدة للمتصفح ووسائل النقل الأصلية | التحقق محليًا وفي CI |

يستخدم أمر الاختبارات الكامل `linux/amd64` لأن امتداد php-rnet الأصلي يُبنى ويُختبر لهذه المعمارية. لا تنشر صورة `ci` ولا تستخدمها في الإنتاج.

عدد عمال البناء الافتراضي هو واحد. يمكن تغييره عند بناء صورة CI مباشرة على جهاز تتوفر لديه ذاكرة كافية ومعروفة:

```bash
docker buildx build \
  --file docker/Dockerfile \
  --target ci \
  --platform linux/amd64 \
  --build-arg BUILD_JOBS=2 \
  --load \
  --tag webtrawler:ci \
  .
```

تستخدم تنزيلات Composer وCargo ومخرجات بناء Cargo آليات BuildKit cache mounts. تكون هذه البيانات ضمن مخزن Builder، ويمكن حذفها عند تنظيف ذاكرة التخزين المؤقت لذلك الـ Builder.

## استكشاف الأخطاء

### Buildx غير متاح

ثبّت أو فعّل إضافة Docker Buildx، ثم تحقق:

```bash
docker buildx version
```

### محرك Docker غير متاح

شغّل Docker Desktop أو Colima، ثم تحقق:

```bash
docker info
```

### فشل تشغيل AMD64 على Apple Silicon

هدف الاختبارات الكامل مخصص لـ AMD64. فعّل محاكاة AMD64 في Docker VM وتأكد من إمكانية تشغيل حاوية بسيطة بمعمارية `linux/amd64` قبل إعادة البناء الكامل.

### نفاد الذاكرة أثناء التجميع الأصلي

اترك `BUILD_JOBS=1` (وهو الافتراضي)، وتجنب بناء صور كبيرة أخرى بالتزامن، وخصص ذاكرة كافية لـ Docker VM. زيادة `BUILD_JOBS` قد ترفع ذروة استهلاك الذاكرة بشكل ملحوظ.

### تخطي اختبار عزل المتصفح

استخدم الأمر `composer test-docker` المرفق. فهو يشغّل صورة CI باستخدام `--network none` ويضبط `SCRAPER_BROWSER_EGRESS_ISOLATED=1` لهذا التشغيل فقط. لا تضبط هذا المتغير لعملية متصفح عادية متصلة بالشبكة.

### تخطي أحد الاختبارات

يتعامل مشغل CI الموحد مع تخطي اختبارات المتصفح أو وسائل النقل الأصلية على أنه فشل. تحقق من اكتمال بناء هدف CI ومن وجود الامتداد الأصلي والمتصفح وملف curl-impersonate. لا تضعف فحص التخطي لمجرد تمرير تشغيل تكامل غير مكتمل.

## نظافة سياق البناء

يستبعد ملف `.dockerignore` في جذر المشروع اعتماديات المضيف ومخرجات البناء والاختبار المحلية وبيانات Git وملفات البيئة المحلية من سياق البناء. كما يستخدم هدف الإنتاج أوامر `COPY` محددة، لذلك لا تعتمد محتويات صورة الإنتاج على الملفات الموجودة في مجلد عمل المطور.

لا تمرر الأسرار عبر Docker build arguments ولا تضع بيانات الاعتماد داخل أي من الصورتين. مرر أسرار التشغيل باستخدام آلية إدارة الأسرار في منصة النشر.
