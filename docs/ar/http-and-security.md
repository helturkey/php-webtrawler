# خيارات HTTP والأمان

تشرح هذه الصفحة ضوابط المكتبة وحدودها. وهي لا تحل محل تحليل التهديدات الخاص بالتطبيق أو عزل الشبكة.

## سياسة الأمان

إذا كان التطبيق يستقبل عناوين URL من المستخدمين، فأنشئ سياسة واضحة وفرضها:

```php
$policy = new FetchOptions(
    timeout: 20,
    connectTimeout: 5,
    verifyTls: true,
    allowRedirects: true,
    maxRedirects: 5,
    maxBodyBytes: 10 * 1024 * 1024,
    blockPrivateNetworks: true,
    allowedHosts: ['catalog.example.com'],
);

$scraper = Scraper::create(
    defaultOptions: $policy,
    enforceDefaultSecurity: true,
);
```

عند تفعيل `enforceDefaultSecurity: true` يتم تشديد خيارات كل طلب وفق السياسة الافتراضية. لا يمكن لخيارات الطلب تعطيل حظر الشبكات الخاصة، أو رفع حد جسم الاستجابة، أو تعطيل التحقق الإلزامي من TLS، أو إعادة تفعيل التحويلات التي عطّلتها السياسة، أو استبدال بروكسي مفروض، أو توسيع قائمة المضيفين. يتم تقاطع قائمتَي المضيفين غير الفارغتين؛ وإذا لم يوجد تقاطع يُرفض الطلب.

عند عدم فرض السياسة الافتراضية، تُستخدم خيارات كل طلب كما قُدمت مع استمرار فحوصات وسيلة النقل. لا تتيح إنشاء `FetchOptions` بلا قيود للمتصلين غير الموثوقين.

## ضوابط SSRF

يفحص حارس URL صياغة العنوان ونتائج DNS، ويرفض المضيفين الذين لا يمكن حلهم، ويمكنه رفض عناوين loopback وprivate وlink-local. تتحقق محولات Guzzle وRnet وImpity المرفقة من وجهات التحويل قبل اتباع قفزات التحويل المدعومة، كما تنفذ فحوصات للوجهة النهائية.

هناك حدود مهمة:

1. قد يتغير DNS بين لحظة الفحص ولحظة الاتصال الفعلي (DNS Rebinding أو TOCTOU). فحص DNS على مستوى التطبيق لا يضمن وحده عنوان المقبس النهائي في كل نظام أو وسيلة نقل.
2. قد لا تنفذ وسائل النقل المخصصة حدود التحويلات نفسها. لا تفترض أن وسيلة نقل خارجية ترث كل ضمانات الأمان لمجرد أنها تطبق `HttpTransport`.
3. قائمة المضيفين قيد توجيه وليست حدًا للثقة في المحتوى. قد يقدم الموقع المسموح محتوى HTML أو تحويلات أو ملفات أو بيانات ضارة.
4. تشغيل المتصفح له قيود إضافية موضحة في [تشغيل المتصفح](browser.md).

للمهام عالية الخطورة، شغّل الجلب خلف Firewall للخروج الشبكي أو Egress Proxy يمنع نطاقات loopback وprivate وlink-local وmulticast وreserved ونطاقات metadata السحابية. امنع التطبيق من تجاوز هذا البروكسي.

## التحويلات وOrigin

يجب فحص كل قفزة تحويل وليس العنوان الأول فقط. لا ينبغي إرسال بيانات اعتماد مرتبطة بالـ Origin، مثل `Authorization` وCookies، عند الانتقال بين Origins مختلفة. يتكون Origin من البروتوكول والمضيف والمنفذ؛ لذا تغيير البروتوكول أو المنفذ يعني Origin مختلفًا حتى لو بقي اسم المضيف نفسه.

استخدم قوائم مضيفين دقيقة للمجالات المعروفة. تجنب السماح بنطاقات أصلية واسعة إذا كانت نطاقاتها الفرعية قابلة للتفويض أو يتحكم بها مستخدمون.

## TLS والبروكسي

اترك `verifyTls=true`. تعطيل التحقق من الشهادات يعرّض الاتصال للاعتراض ويُضعف افتراضات أمان النقل.

بيانات اعتماد البروكسي أسرار. مررها من متغيرات البيئة أو مدير أسرار، ولا تحفظها في الكود أو Fixtures أو السجلات. قد تحتوي عناوين البروكسي على بيانات اعتماد في userinfo أو المسار أو Query أو رموز خاصة بالمزود. تخفي المكتبة عناوين البروكسي في إحصاءاتها وأخطائها، لكن يجب مراجعة سجلات التطبيق أيضًا.

يدعم `ProxyPool` استراتيجيات round-robin وrandom وleast-failures، ويتابع الإخفاقات والنجاحات، ويطبق فترة Cooldown على البروكسي غير السليم، ثم يسمح بمسبار واحد Half-open بعد انتهاء الفترة. إذا كانت جميع البروكسيات في فترة انتظار، يفشل الحصول على بروكسي ما لم يُفعّل direct fallback صراحة في `ProxyTransport`. السماح بالاتصال المباشر قرار أمني؛ اتركه معطلًا إذا كان استخدام البروكسي إلزاميًا.

يضبط مزود خدمة Laravel مجموعة البروكسي لطلبات HTTP وSpider، لكنه لا يمررها تلقائيًا إلى Playwright؛ يحتاج المتصفح إلى بروكسي خاص به أو توجيه إجباري على مستوى الشبكة.

## حدود الاستجابة والترميز

الحد الافتراضي لجسم استجابة HTTP هو 20 MiB. اختر حدًا أصغر للمواقع غير الموثوقة. تمرير `null` يعطل هذا الحد ولا يُنصح به مع عناوين URL عشوائية. تحمي هذه الحدود مسار التقاط جسم HTTP، لكنها لا تقيد تلقائيًا كل موارد المتصفح الفرعية أو كل الذاكرة التي قد يخصصها محرك المتصفح.

استخدم `encoding` فقط عندما يكون ترميز المصدر معروفًا. وتحتاج أجسام الطلب غير UTF-8 والحالة القابلة للاستئناف إلى عناية خاصة؛ إذ ترفض حالة الزحف القيم غير المدعومة أو غير الآمنة بدل تغيير الطلب بصمت.

## السجلات والاحتفاظ بالبيانات

- لا تسجل ترويسات المصادقة أو Cookies أو بيانات البروكسي أو أجسام الاستجابات أو محتويات ملفات حالة المتصفح الخام.
- استخدم `Page::url()` بحذر؛ فقد يحتوي العنوان النهائي على قيم Query حساسة أضافها الموقع البعيد. نقّحه قبل التسجيل.
- تنقّح أخطاء الزحف وتشخيصات URL المدمجة عددًا من القيم، لكن Middleware وPipeline المخصصين مسؤولية التطبيق.
- حدد مدد الاحتفاظ باللقطات وحالة الزحف والبيانات المصدرة وبيانات المتصفح.
- احفظ الأسرار خارج ملفات المستودع وسياق بناء الحاويات.

## اختبارات الأمان

شغّل اختبارات الأمان ضمن `composer test`، واختبارات وسائل النقل الأصلية، واختبار Chromium المعزول. وبالنسبة إلى SSRF في المتصفح، استخدم عزلًا شبكيًا حقيقيًا إضافةً إلى اختبارات Routing. راجع [الاختبارات وCI والإصدار](testing-and-release.md).
